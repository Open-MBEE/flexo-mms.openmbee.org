Open-MBEE · RDF · SPARQL 1.1 · SysML v2 API

Model management for models that are graphs.

Flexo stores a model as RDF in a SPARQL quadstore and gives it the shape of a version-controlled repository: organisations, repositories, branches, commits, locks and diffs, with SPARQL to read and write and policies deciding who may. On top of that one store it serves the OMG SysML v2 API and Services, so standard modelling tools get real branching and history without knowing what is underneath — and around it are a git-style CLI, MCP servers for AI assistants, Python clients and a web modeler.

The architecture

Small services, one contract: a SPARQL quadstore underneath, a JWT between them.

Every layer talks to the one below it over a standard protocol and can be replaced or scaled on its own. Each service is a repository and a container image; the architecture page follows a request from a client to the store and back.

Clients and tools People and programs The CLI, MCP servers, Python clients, the web modeler, and any tool built to the SysML v2 API. flexo-cli-client · flexo-mms-layer1-mcp · sysmlv2-python-client · sysmlv2-web-modeler Layer 2 Domain APIs The OMG SysML v2 API and Services, and GraphQL, each translated onto the layer below. flexo-mms-sysmlv2 · flexo-graphql Layer 1 Flexo MMS Orgs, repos, branches, commits, locks, diffs and policies; SPARQL query and update; large loads through the store. flexo-mms-layer1-service · flexo-mms-auth-service · flexo-mms-store-service Layer 0 Storage Any SPARQL 1.1 quadstore — Fuseki, GraphDB — holding models and metadata alike, an S3 bucket beside it, and a dashboard onto the graphs. fuseki · minio · flexo-mms-layer0-dashboard

Flexo is the successor to the document-oriented MMS, now exec-mms, and is not a drop-in replacement for it: it stores RDF and versions the graph itself. Older material calls it MMS5; the name refers to the same system.

The services

Layer 1

The model management API. Version control for a graph — branches, commits, locks, diffs — read and written with SPARQL 1.1, guarded by policies evaluated on every request.

SysML v2 API and Services

The OMG standard REST API over Layer 1: projects, commits, branches, tags and elements, for every modelling tool that speaks it.

Authentication

An LDAP bind, or an OAuth2/OIDC login or API key in the SSO service, exchanged for the signed JWT every other service trusts.

Store

Large loads staged in S3-compatible storage, so the quadstore fetches a model by URL instead of streaming it through the API.

GraphQL

A GraphQL schema over any branch, compiled to SPARQL through a JSON-LD context, with GraphiQL to explore it.

Layer 0 dashboard

An administrator's view straight onto the named graphs in the quadstore, for bootstrapping and repair.

Deployment

A Docker Compose stack for one machine and Kubernetes manifests for a cluster, with the guide that documents every variable.

Clients and tools

Flexo CLI

init, push, pull, branch, merge, remote — a Flexo repository handled like a git remote, with a plugin for the SysML v2 API.

MCP servers

Layer 1 and the SysML v2 API as Model Context Protocol tools, read-only by default, acting as the user whose token they forward.

Python

A SysML v2 API client, and flexo_syside to move SysML v2 textual notation in and out of Flexo through SysIDE.

SysML v2 Web Modeler

Graphical rendering and textual editing of SysML v2 in the browser, against any SysML v2 API, standalone or embedded in JupyterLab.

Libraries and integrations

The Flexo MMS ontology, the Jama requirements SDK, model-based pull requests, and a performance test suite.

OpenSysML

Open-MBEE's SysML v2 toolchain — parser, validator, runtime, LSP — which exports the RDF that Flexo stores.

Get started

# Flexo MMS: LDAP, Fuseki, MinIO, and the Auth, Store and Layer 1 services
git clone https://github.com/Open-MBEE/flexo-mms-deployment.git
cd flexo-mms-deployment/docker-compose && docker compose up

# The SysML v2 API, with its Flexo MMS prerequisites
git clone https://github.com/Open-MBEE/flexo-mms-sysmlv2.git
cd flexo-mms-sysmlv2 && docker compose -f docker-compose/docker-compose.yml up -d

Layer 1 answers on localhost:8080 and the SysML v2 API on localhost:8083; the getting started page has the first requests, and the deployment page covers Kubernetes.
